# 聖火降魔錄 萬縷千絲（萬紫千紅）培養計算器：成長率公式與坐騎加成

<web-summary>《聖火降魔錄 萬縷千絲》（萬紫千紅）的角色成長是個人、職業與坐騎成長率逐級擲骰，職業補正只在當下職業生效；從遊戲內目前的等級、職業與實際能力值出發預測轉職路線，並整理凱伊篇坐騎與戰車兵的成長加成規則。</web-summary>

要預測角色練到某個等級的能力，要從**遊戲內目前的等級、職業、坐騎與實際能力值**開始算，再逐段套用之後各職業的成長率，結果才會貼近遊戲。我把這個流程做成繁中網頁：[萬紫千紅 培養計算器](https://fe-banshisenko-calc.jakeuj.com/)，除了期望值與機率區間，也算進凱伊篇坐騎的成長加成。

<tldr>
<p>每級成長率 = 個人 + 職業 + 坐騎成長 × 倍率；戰車兵的坐騎成長加成 ×2。</p>
<p>職業補正只在該職業時生效，換職業就換一組，所以起點要填遊戲當下的顯示值。</p>
<p>馬系坐騎的成長加成不是能力加成 ×5，而且包含 HP。</p>
</tldr>

以下內容整理於 2026 年 10 月。數值以 game8 計算器的資料為基礎，部分職業與角色已用遊戲內成長畫面修正；遊戲更新後可能變動，實際以遊戲畫面為準。

## 為什麼 game8 的預測跟遊戲對不上 {#why-game8-differs}

game8 的「育成方針計算ツール」從角色的預設加入狀態開始算，只能改加入等級，不能改職業。以索緋雅（ソフィア）為例，預設是 Lv8 詛咒師，但在凱伊篇招募到時已是 Lv29 牧師。把加入等級改成 29，工具會假設 Lv8 到 29 全程都用詛咒師的成長率，因此有三個偏差：

- 詛咒師與牧師的成長率不同。
- 職業補正不同：詛咒師是魔力 +1、魔防 +1；牧師是魔力 +1、魔防 +3、幸運 +2、魅力 +1。
- 升級本身是機率事件，實際值本來就會偏離期望值。

改成從遊戲當下的實際數值出發，前面這些假設造成的誤差就不會帶進預測。

## 成長率公式 {#growth-formula}

- 每級成長率 = 個人 + 職業 + 坐騎成長 × 倍率 + 戰車加成，小於 0 視為 0。
- 每升一級，9 項能力各自擲骰：成長率在 100 以下時，以該機率 +1；超過 100 時先確定 +1，超出的部分再以機率 +1。
- 顯示值 = 內部值 + 目前職業補正 + 坐騎能力加成。補正與坐騎能力加成只在該職業、騎乘時存在；轉職不重置等級，也沒有額外的轉職加成。
- 期望值的四捨五入與 game8 相同：各項是期望內部值四捨五入後再加補正；合計是先把期望值加總再四捨五入，所以可能和各項相加差 1。

用 game8 計算器的推薦路線逐值核對（索緋雅 Lv8 詛咒師 → Lv20 詛咒師 → Lv35 牧師 → Lv45 主教 → Lv99 賢士），四個節點的合計 134、194、241、463 與 game8 的輸出完全一致。

每項能力的升級結果可以逐級算出完整的機率分布，因此除了期望值，也能列出常見範圍，並把實際練出來的數值換算成百分位：前 5 百分位內為神成長、前 25 百分位內為良成長、前 75 百分位內為普通，其餘偏低（與 game8 的判定標準相同）。

## 坐騎（騎乘動物）加成 {#mount-bonus}

- **取得**：只有凱伊篇（第 1 部第 5 章起）與救世篇能在大地圖誘捕；其他路線只能用伊歐加入時附帶的羅西南、亞歷山卓附帶的布克發拉斯。
- **友好度**：能力與成長加成會隨友好 Lv1 到 Lv5 提高。目前只有滿級 Lv5 的數值可靠，Lv1 到 Lv4 各級加在哪一項沒有公開資料。
- **成長加成**：飲魯尼魯斯（鴕鳥）、飛馬、巴烏系是能力加成 ×5；**馬系不是**，成長分配不同而且包含 HP。game8 有一張凱伊（榮光騎士）配野生馬的遊戲截圖：成長率 HP、速度、技巧、防守、魔防各 +5，能力卻只有速度 +1、技巧 +3、防守 +1。

| 坐騎 | 能力加成（Lv5）| 成長加成（Lv5）|
| ------ | ------ | ------ |
| 野生馬 | 速 1、技 3、防 1 | HP 5、速 5、技 5、防 5、魔防 5 |
| 汗血馬 | 力 2、技 1、防 2 | HP 5、力 5、技 5、防 10 |
| 莫諾凱洛斯 | 速 1、技 1、運 3 | HP 5、速 5、技 5、魔防 10 |
| 野生飲魯尼魯斯 | 速 2、技 3 | 速 10、技 15 |
| 野生飛馬 | 速 3、魔防 2 | 速 15、魔防 10 |

坐騎類型要與職業相符才有加成：

| 坐騎類型 | 可配屬的職業 |
| ------ | ------ |
| 馬 | 輕騎兵、戰車兵、森林騎士、榮光騎士、遊唱詩人、重裝騎兵、奧利哈鐵騎、弓騎士、英勇騎士、瓦爾基里姆、高階墓誌銘、烈駿神將 |
| 飛鴕 | 飛鴕兵、騎甲鴕兵、神鴕兵 |
| 天馬 | 天翼兵、聖天翼兵（兩者皆女性限定）|
| 飛龍 | 馭龍兵、飛龍將領 |

戰象兵沒有可捕獲的象坐騎。歐露赫露、哥萊亞斯的個人技能讓他們無法轉職為騎兵或飛行兵種。最上級與神將職業的繁中名稱多為由簡中轉換的暫譯。

### 戰車兵 {#charioteer}

- **坐騎成長加成 ×2**：戰車由兩匹馬拉動。皮特魯 Lv26 戰車兵配汗血馬時，遊戲成長畫面的「賦予」欄是 HP 10、力 10、技 10、防 20，正好是汗血馬的兩倍。
- **戰車兵之道**：戰車本身也有成長加成，會隨升級提高。社群表列出多輪升級後為 HP +10、力 +15、魔 +5、速 +5、技 +10、防 +20、魔防 +5、運 +5、魅 +10；這組數字加上個人、職業與汗血馬 ×2，與馬吉迪實測的 HP 95、力 80、技 65、防 90 逐項吻合。戰車加成何時開始、何時升級沒有公開資料，而皮特魯 Lv26 的成長畫面還沒有任何戰車加成，所以計算器預設不計，可在路線中手動選擇。
- 坐騎的**能力**加成是否也 ×2 目前未知，計算器以 ×1 計算。

## 用遊戲內成長畫面確認數值 {#verify-in-game}

各攻略站的成長率常有出入，最可靠的是遊戲內的角色成長畫面。它分成四欄：

- **基本值**：角色個人成長率。
- **兵種**：職業成長率。
- **賦予**：坐騎成長加成 × 倍率。
- **最終面板**：合計；比前三欄多出來的部分就是戰車加成。

能看分欄時直接逐欄比對即可。只看得到合計時，選一個各來源數值都一致的職業、不要配坐騎，就能反推：個人 = 顯示 − 職業，或職業 = 顯示 − 個人。例如哪吒當劍客（劍客力量成長 +0）時力量顯示 45，所以個人力量成長是 45，而不是 game8 寫的 55。

## 資料來源與已知差異 {#data-sources}

- 角色與職業的成長率、補正、加入資料：game8 計算器背後的公開 JSON，不必解析網頁。
- 坐騎與戰車：game8 各動物頁、game8.co、簡中 wiki（fire-emblem-fw.site）與騰訊文件社群表。
- 中文名稱：繁中社群整理的試算表、巴哈姆特與 GNN 文章；找不到繁中來源的才由簡中轉換。

各站最常見的差異是職業的速度與技巧兩欄對調。採用順序是：遊戲畫面實測、多個獨立來源一致、game8 計算器、單一來源。依此目前修正了 game8 的 13 個數值，例如：

| 項目 | game8 | 採用 | 依據 |
| ------ | ------ | ------ | ------ |
| 榮光騎士技巧成長 | +5 | 0 | 凱伊的遊戲截圖 |
| 戰車兵技巧成長 | +25 | +15 | 皮特魯 Lv26 成長畫面「兵種」欄 |
| 哪吒個人力量成長 | 55 | 45 | 劍客時成長畫面顯示 45 |
| 宗師射手速度、技巧成長 | +20、+15 | +15、+20 | game8.co、簡中 wiki、騰訊文件表一致 |

其餘只有單一來源不同的項目維持 game8 的數值，計算器的「資料／校正」頁可讓玩家改成自己在遊戲內看到的值。

## 計算器的實作方式 {#how-it-is-built}

- **單頁靜態網站**：`index.html`、`calc.js`（計算）、`app.js`（介面）與產生出來的 `data.js`，可直接開啟，也部署在 GitHub Pages。
- **資料流程**：`node tools/build-data.mjs --refresh` 下載 game8 JSON，套上中文名稱對照、坐騎表與修正清單後產生 `data.js`；網頁執行時不抓第三方資料。
- **測試**：計算核心不碰 DOM，Node 可以直接呼叫；`node tools/test-calc.mjs` 確認與 game8 輸出逐值一致，並包含上面的實測案例。
- **機率分布**：每項能力存「起點值＋增量的機率陣列」，每升一級做一次卷積；物理、魔法等群組判定再把多項分布卷積起來。
- **自動推薦**：依各階可轉職的等級把路線切段，每段挑每級期望加權收益最高的職業，騎乘職自動配上最佳坐騎，最後一段再加上最終職業的補正。
- **使用者資料**：每個角色的起點、路線與資料校正只存在瀏覽器的 localStorage。

自訂子網域的設定方式：DNS 加一筆 `CNAME` 指向 `<username>.github.io`，repo 根目錄放一個內容為網域名稱的 `CNAME` 檔（從分支發布時，GitHub 以這個檔記錄網域），再設定 Pages 並開啟強制 HTTPS：

```bash
gh api -X PUT repos/<owner>/<repo>/pages -f cname=<sub>.<your-domain>
gh api -X PUT repos/<owner>/<repo>/pages -F https_enforced=true
```

第二行要等 GitHub 核發憑證後才會成功。帳號本身已設定自訂網域時，沒加 `CNAME` 的專案網站會出現在 `<your-domain>/<repo>/` 底下。網域驗證與 DNS 記錄可參考 [Domain](DNS.md)。
